# 操作改善：精確重播與鍵盤檢視

[返回作品介紹](../README.md)

本次沿用 Phase 1.2 的 Rust 搜尋與事件契約，改善重播操作及節點檢視。既有 Phase 1.2 報告保留為歷史驗收證據；本頁說明後續變更，不重寫先前的數字。

## 不必點 Canvas，也能選取節點

執行後進入「檢視」，輸入欄座標 x、列座標 y，再按「檢視座標」。座標從 0 開始，32×32 網格的範圍是 0–31；空白、小數與超出網格的值不能提交。

選取只改變檢視節點，不重新搜尋。既有 Canvas 點選仍可使用；座標選取並不代表整張 Canvas 已具備完整的螢幕閱讀器導覽。

## 精確跳轉與快捷鍵

展開播放控制中的「精確跳轉與鍵盤快捷鍵」，輸入 0 到目前總長度之間的整數，按「跳至位置」。跳轉會暫停播放，並使用目前的事件、展開數或百分比同步模式；共享時鐘位置不一定等於每個演算法的事件 ID。

| 快捷鍵 | 行為 |
| --- | --- |
| 空白鍵 | 播放／暫停；在結尾開始播放時從頭重播 |
| 左／右方向鍵 | 後退／前進一個共享時鐘單位 |
| Shift＋右方向鍵 | 下一次節點展開 |
| Home／End | 跳到開頭／結尾並暫停 |

快捷鍵只在目前實驗的競賽、檢視或分析畫面啟用。輸入框、下拉選單、滑桿、按鈕、連結、可編輯內容及 details 標題保留原有鍵盤操作；地圖編輯、Benchmark、首頁、計算中與導覽期間不啟用全域重播快捷鍵。重複按住、輸入法組字與 Ctrl／Alt／Meta 組合也不接管。

## 啟發函數實驗可重複執行

四種啟發函數與 Dijkstra 參考的五組設定獨立保留。按「開始競賽」會重新執行相同五組設定，而不回到先前的一對一組合。重新生成或編輯網格後，仍沿用選定的比較設定；改成一對一或四方競賽則依目前參賽者執行。

## Windows 保留埠的測試方式

程式預設仍使用 1431。若 Windows 將該埠列入保留範圍，可以指定其他本機埠，不需更動系統保留規則：

```powershell
# 瀏覽器開發介面
npm run dev -- --port 31431

# E2E 會在相同埠啟動或重用開發伺服器
$env:ARENA_TEST_PORT = '31431'
npm run test:e2e
```

桌面開發的 Tauri devUrl 仍是原設定；上述覆寫只適用於瀏覽器開發與 E2E，不變更封裝程式。

[新增 E2E](../tests/e2e/navigation.spec.ts) 直接操作真實 Rust adapter，驗證雙語跳轉、原生控制項不受快捷鍵干擾、座標邊界、編輯模式不接管快捷鍵，以及操作前後匯出內容逐位元組一致。啟發函數測試比對再次執行前後的完整 config 與 canonical hash。

2026-10-11 本機驗證：Rust **39**、前端單元測試 **48**、完整 E2E **36** 全部通過；E2E 沒有失敗、flaky 或 skipped。型別檢查、lint 與 production build 通過。雙語字典為 **384 keys**，缺漏 **0**。

Browser plugin 未提供，畫面檢查使用既有 Playwright：`http://127.0.0.1:31431/`，雙語各檢查 1536×1024 與 390×844 的座標選取、位置跳轉和播放／暫停。頁面標題正確、無空白或 Vite error overlay，console errors **0**，頁面水平溢出 **0**。既有完整 E2E 另外涵蓋 1920×1080、1536×864、1366×768 與 390×844。

匯出流程會先觸發下載，再延後釋放 Blob URL，避免同一個 click handler 中立即釋放 URL。內容仍使用相同 canonical RunLog，未變更資料格式。
